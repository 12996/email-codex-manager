# PRD-001 项目文档管理体系

状态：active

## 背景

大型 vibe coding 项目需要稳定文档体系，帮助 AI 恢复上下文，并帮助人类追溯需求、文档结构、问题、决策和工作过程。

## 目标

- 文档分层明确：模板、记忆、需求、项目说明、问题、工作记录不混放。
- AI 能快速定位相关文档。
- 人类能追溯项目演进。
- 文档不过度碎片化。

## 范围

- 包含：`AGENTS.md`、`docs/README.md`、`docs/prd/`、`docs/project/`、`docs/templates/`、`docs/memories/`、`docs/issues/`、`docs/work/`
- 不包含：具体业务需求、具体业务架构、数据模型、一次性聊天流水

## 验收标准

- [x] `AGENTS.md` 是精简版 AI 导航协议。
- [x] `docs/README.md` 是文档总入口。
- [x] 每个核心目录有入口文件。
- [x] 信息归属清晰。
- [x] 建立了轻量化的 Change 变更记录机制，在 implemented change 达到 5 个时触发合并 PRD 提醒。

## 5. 变更管理规范

当修改系统流程、交互、权限、数据规则或长期规则时，必须在 `docs/changes/` 创建单文件变更记录，并在 `CHANGE_REGISTRY.md` 中进行登记。
变更生命周期：`draft` 草案 -> `accepted` 确认 -> `implemented` 已实现但未合并 -> `merged` 已合并到 PRD 基线。
当未合并的 `implemented` 变更达到 5 个时，AI 须提醒用户进行基线合并。合并后，应删除临时非标准文档（如 `plans/` 下的过程实现方案），同时将变更文件状态更新为 `merged` 并记录合并日期与合并目标 PRD。
