# 2026-07-03 注册超时恢复兼容回到密码页

## 目标

修复 OpenAI 注册流程中，密码提交后进入邮箱验证码阶段遇到 `Operation timed out`，点击“重试”后回到创建密码页导致自动化误填 OTP 的问题。

## 根因

run `351` 的失败截图显示页面实际停在 `Create a password`，而不是邮箱输入页或 OTP 页。错误栈显示脚本在 `submitOtpWithRetry()` 中使用 `input[type="text"]` 兜底 selector，命中了页面上的只读邮箱输入框，`fill()` 等待元素可编辑超时。

## 变更

- OTP 输入框识别增加可编辑性和字段语义检查，排除只读邮箱输入框。
- OTP 等待阶段发现创建密码页时，重新填写数据库密码并提交。
- 如果验证码已经获取后才恢复到密码页，当前验证码作废，重新轮询下一封验证码。
- 抽出 `submitRegistrationPassword()` 复用首次密码页和恢复后的密码页处理。

## 验证

- `node --test test\roxyRegisterOpenai.test.js`：13/13 通过。

## 后续

需要重启当前服务后，新注册子进程才会加载该修复。建议下一次真实注册观察日志中是否出现：

- `OTP 阶段回到了创建密码页`
- `页面恢复后需要重新拉取验证码`

若出现上述日志且后续注册成功，说明该异常路径已被自动恢复。
