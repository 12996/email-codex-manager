# 补号账号开通方式下拉与页面维护设计

- 状态：approved
- 创建日期：2026-07-14
- 关联 PRD：PRD-003
- 关联 Change：CHG-077

## 背景

`replacement_accounts.activation_method` 已存在，但补号管理页当前使用普通文本输入和文本展示。账号状态已经支持列表内下拉修改，开通方式也需要采用同样的直接操作方式。

当前初始开通方式为：

- 越南直卡
- `upi`
- `ideal`
- 波兰
- 瑞士
- `pix 直卡`

后续开通方式可能继续增加，因此不能把选项永久硬编码在 HTML 中。

## 目标与范围

- 将列表“开通方式”列改为行内下拉框。
- 选择后立即通过独立 API 保存，不打开账号编辑弹窗。
- 页面提供开通方式管理入口，可新增方式。
- 新增方式立即出现在列表和账号编辑弹窗的下拉框中。
- 保留现有 `activation_method` 字符串字段和历史数据，不做账号表外键迁移。
- 不提供删除方式，避免已有账号出现失效引用。

## 方案决策

采用“数据库方式目录 + 账号字符串字段”的方案。

| 方案 | 优点 | 缺点 | 决策 |
|---|---|---|---|
| 代码常量 | 代码量少 | 新增方式必须改代码并发布 | 不采用 |
| 数据库目录 + 字符串字段 | 页面可新增、兼容旧数据、无账号表迁移 | 需要维护一个目录表 | 采用 |
| 账号外键关联方式表 | 数据关系严格 | 需要迁移历史值，删除/重命名风险更高 | 不采用 |

## 数据模型

新增 SQLite 表 `replacement_activation_methods`：

| 字段 | 说明 |
|---|---|
| `id` | 自增主键 |
| `name` | 展示值和账号保存值，不能为空且忽略大小写去重 |
| `created_at` | 创建时间 |
| `updated_at` | 最后更新时间 |

数据库初始化时使用幂等种子写入上述 6 个初始方式。现有 `replacement_accounts.activation_method` 保持不变，允许为空。

## 页面与数据流

### 列表行内修改

1. 页面加载开通方式目录和账号列表。
2. “开通方式”列显示下拉框，默认包含“未设置”和目录中的全部方式。
3. 当前账号已有但不在目录中的历史值仍作为临时选项显示，并标记为“历史值”。
4. 用户选择新值后立即调用 `PATCH /replacement-accounts/:id/activation-method`。
5. 成功后刷新列表并记录“开通方式已更新”；失败后恢复原值并提示错误。

### 管理新增方式

1. 页面点击“管理开通方式”。
2. 弹窗展示当前方式并提供新增输入框。
3. 提交 `POST /replacement-activation-methods`。
4. 后端 trim、校验非空和大小写不敏感重复。
5. 成功后刷新目录、关闭或更新弹窗，并让新方式立即可选。

账号新增/编辑弹窗中的开通方式字段也改为目录下拉框；空值使用“未设置”。

## API

### `GET /replacement-activation-methods`

返回按创建顺序排列的方式目录。

### `POST /replacement-activation-methods`

请求体：

```json
{
  "name": "新方式"
}
```

空值返回 `ACTIVATION_METHOD_REQUIRED`，重复值返回 `ACTIVATION_METHOD_DUPLICATE`。

### `PATCH /replacement-accounts/:id/activation-method`

请求体：

```json
{
  "activation_method": "upi"
}
```

空字符串用于清空方式；非空值必须存在于方式目录中。账号不存在返回 `ACCOUNT_NOT_FOUND`。

## 兼容性与安全边界

- 不修改旧账号的 `activation_method` 数据。
- 旧值不在目录时不自动覆盖，也不阻塞列表展示。
- 目录只允许新增，不允许删除，避免破坏历史账号。
- 所有目录和账号修改接口沿用后台登录态。
- 现有状态下拉、补号流程和账号编辑 API 保持原行为。

## 验收标准

- [ ] 六个初始方式出现在列表和账号编辑下拉框。
- [ ] 列表下拉修改后刷新页面仍保持新值。
- [ ] 保存失败时下拉框恢复原值。
- [ ] 页面可新增第七个方式，并立即出现在所有下拉框。
- [ ] 空值和重复方式被拒绝。
- [ ] 旧历史值继续显示且不丢失。
- [ ] 状态下拉及其他账号操作回归通过。

## 回滚

代码回滚后保留 `replacement_activation_methods` 表不会影响旧版本；如需完整回滚，可删除该表，但必须先确认没有依赖新增目录的账号值。`activation_method` 原字段不需要数据转换。
