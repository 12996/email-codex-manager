# 补号状态查询实时进度窗口设计

- 状态：approved
- 创建日期：2026-07-14
- 关联 PRD：PRD-003
- 关联 Change：CHG-079

## 目标

“一键验活”和“查询 Plus 状态”执行期间立即打开进度窗口，实时显示每个账号的处理阶段和结果，完成后保留日志与汇总，用户手动关闭。

## 方案

保留现有两个 JSON API 的默认行为，新增通过 `Accept: text/event-stream` 请求头触发的 SSE 流式响应。后端服务增加可选 `onProgress` 回调，在候选账号开始、读取邮箱、命中/未命中/失败时发送结构化事件。前端用 `fetch().body.getReader()` 消费事件并渲染进度窗口。

## 事件

- `start`：任务名称和总账号数。
- `account-start`：账号开始处理。
- `account-step`：正在选择收件箱、读取邮件等阶段信息。
- `account-result`：命中、未命中或失败。
- `complete`：最终汇总结果。
- `error`：服务级错误。

## 交互

- 点击按钮并确认后立即打开窗口，日志区域自动滚动到底部。
- 执行期间关闭按钮保持可用，但不会取消后端任务。
- 完成后窗口不自动关闭，显示最终汇总。
- SSE 失败或服务错误也写入窗口，不只显示 toast。

## 兼容性

- 不改变现有 JSON API 调用方。
- 不改变 Plus 命中后的 `plus_active` 状态写回逻辑。
- 单账号失败继续处理后续账号。

## 验收

- [ ] 两个按钮点击后立即显示进度窗口。
- [ ] 窗口实时显示账号级开始、读取、结果日志。
- [ ] Plus 命中后账号状态仍更新为 `plus_active`。
- [ ] 验活命中后账号状态仍更新为 `banned`。
- [ ] 完成后显示汇总且窗口保持打开。
- [ ] 旧 JSON API 测试继续通过。
